适合做研究预览版
1. 问题重构 用户真正困境

不是“想要一个炫酷政策导航系统”，而是在多 agent、知识库、NAS、Gateway、任务验收交织时，用户无法快速判断：当前行动是否被允许、依据是否可信、失败后怎么回滚。

2. 目标用户和场景 NJX / OpenClaw 操作员

在开发台推进任务、保存知识、开启 cron、派发 sub-agent、处理高风险动作前，需要 10 秒内看清策略命中、证据源、人工审批和下一步。

3. 产品方案 Policy Lens：任务执行控制台的深色策略导航层

核心交互是“左侧策略域、中间决策路径、右侧验收栏”。用户选中一个任务或 agent 动作后，系统展示命中的权限、数据源、验收、成本和安全策略；若通过，给出继续执行按钮；若不通过，显示 hold 原因、证据缺口和回滚路径。

4. 技术方案对比 不为 AI 而 AI：规则层先行，LLM 只在高价值解释处介入。
方案 Latency Accuracy Cost 判断
规则 + 现有 API 聚合：development、agents、system review、audit logs 低，目标 < 500ms 高，适合权限/状态/证据路径 低，无默认 token 成本 推荐作为 v0 研究预览版主路径
RAG + LLM 策略解释：读取 AGENTS、PRD、memory、知识库文档后生成解释 中高，2-8s 中高，取决于引用质量 中，需要 token 预算与缓存 仅用于“为什么这么判定”的长解释，不阻塞主流程
Agent 自动决策并执行策略修复 高，不稳定 风险高，容易越权 高，循环成本不可控 当前不做，只允许生成建议和待审批任务

成功指标、不做的事、风险兜底 这些是开发前的验收合同，不是事后解释。
6. 成功指标
  • 首次判断“继续 / 暂停 / 需审批”的时间从 2-5 分钟降到 20 秒内。
  • 策略判定可解释率达到 95%：每个结论至少有 1 个来源和 1 个下一步。
  • 高风险动作误放行率为 0；无证据时必须 hold。
  • 研究预览版 3 个真实任务样本全部通过桌面 1440、平板 1024、手机 390 视口检查。
7. 不做的事
  • 不把 njx copilot 全站改成暗黑政策大屏。
  • 不做没有证据来源的炫酷数字、热力图或动态图谱。
  • 不让 LLM 直接决定权限、审批、删除、外发、写入长期记忆。
  • 不复刻小红书原帖未验证的图片、布局或文案细节。
8. 风险与兜底
  • 外部链接不可读：只使用可见标题做灵感，不伪造原帖内容。
  • 状态数据缺失：显示 unavailable reason，而不是填假数据。
  • 动画干扰阅读：默认只用于扫描线和状态脉冲，支持 reduced motion。
  • 接口延迟：规则判定先返回，LLM 解释异步生成。
