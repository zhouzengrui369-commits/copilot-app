1 一句话看明白

OpenClaw Workbench = 你说一句话，Workbench 把这件事做完整，并在桌面端给出可验收的证据。

它对标什么

对标 OpenAI Codex CLI，但走更严格的路线：

维度Codex CLIWorkbench
用户入口命令行 sandbox自然语言一句话（比如"修复笔记生成慢"）
运行环境云端 sandboxMac mini 桌面端真实操作（真打开 Chrome / 真截图）
验收方式命令行输出截图证据链 + 人类拍板 ACCEPT / REJECT
失败恢复整段重试局部 patch + recovery packet（用户决策）
自我演进无agent 自己反思 → propose 改进 → 用户决策

它跟其他 AI 产品的关键区别

不是聊天界面 — Workbench 是 Owner Operator 控制台（你来指挥，agent 执行 + 给证据）。
不做"假装 OK" — 某个依赖坏了，永远显示 DEGRADED / BLOCKED，不会包装成 Working。
不做"假证据" — 验收截图必须真实桌面操作，不允许 mock。
不无审计自动决策 — 高风险动作（删数据 / 发版 / 对外发通知）走 approvals 表，等你拍板。

2 开发铁律（6 条 gate）

写在 development-gates.json 里，是所有开发动作必须过的关卡。每一道都不可绕过。

# Gate 名称 类别 具体规则
1 必过 PRD 必须存在 产品 无 PRD 不进入 build。任何功能动工前必须有产品需求文档。
2 必过 原型验收必须存在 产品 核心 UI 改动必须先有人工确认原型或截图证据。不能闷头写代码。
3 必过 测试证据必须存在 工程 必须依次跑通：npm run check && npm run build && npm run test:prd && npm run test:e2e。无测试证据不进入 release。
4 必过 安全扫描必须通过 安全 npm run security:scan — 外部通知、文件访问、发布动作必须经过安全边界检查。
5 必过 正式发布必须审批 发布 人工审批关：gateway 重启、外部通知、生产发布、删受保护文档、付费资源 — 必须你点头。
6 必过 禁止 fake OK 自治 web_search / NAS / MiniMax / gateway 任一不可用时，必须显示 DEGRADED 或 BLOCKED，不允许包装成正常。

对 Vibe Coding 的含义

  • 你给一句话，agent 会自动去查 PRD、看原型、跑测试、出安全扫描报告。
  • 任何一个 gate 没过，它会停下来告诉你为什么，不会假装通过。
  • Gate 5（发布审批）永远要你点头 — 这是设计上故意的，不让 agent 越权。

3 数据存在哪里

所有数据存一个 SQLite 文件，路径 data/workbench.sqlite（22 MB），用 WAL 模式（写不阻塞读）。

关键事实

  • 数据库类型：SQLite（单文件、零运维、内嵌式）
  • 并发模式：WAL（Write-Ahead Logging）+ busy_timeout 5s
  • 外键约束：开启
  • 迁移机制：应用启动时跑 db.ts:migrate()，所有表都是 CREATE TABLE IF NOT EXISTS（幂等）
  • 备份：每天执行 npm run backup:db（脚本在 scripts/backup-db.mjs）

表结构分 8 大块（100+ 张表）

用户与认证

users / sessions / audit_logs

单用户密码登录 + token 会话 + 全量操作审计。

任务编排

tasks / task_dependencies / task_events

任务中心：创建 / 依赖 / DAG / 审批式暂停重试终止。

开发流水线 (核心)

development_goals / development_subtasks / development_runs

Goal → 子任务 → 执行 run → 验收 — 整套自主开发状态机。

知识库

knowledge_entries / knowledge_links / knowledge_wiki_*

笔记生成 v3 的产物入库和反向链接。

OPC 业务（主业延伸）

opc_orders / opc_shipments / opc_kpis / opc_cashflows

航材 / 维修订单、发货、KPI、现金流 — 真实业务飞轮数据。

移动端

mobile_devices / mobile_pairing_challenges / mobile_voice_notes

iPhone 配对、设备注册、语音笔记。

项目与里程碑

projects / project_milestones / project_deliverables

项目管理、里程碑、可交付物。

研究 & 报告

research_jobs / reports / skill_catalog

Deep Research 任务、报表、技能目录。

一条表结构示例（看一眼就好）

-- 核心表：开发目标（用户输入一句话 → 落地成一行）
CREATE TABLE development_goals (
  id              TEXT PRIMARY KEY,        -- UUID
  title           TEXT NOT NULL,
  objective       TEXT NOT NULL,
  success_criteria TEXT NOT NULL,           -- JSON 数组
  status          TEXT NOT NULL,           -- init / running / done / failed
  owner_session_id TEXT,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);

对 Vibe Coding 的含义

SQLite = 单文件 = 易备份易迁移。你想"重置到某个时间点"，直接拷贝 workbench.sqlite 备份即可。所有数据 不出本机，符合"前端不直接访问 ~/.openclaw/"的安全边界。

5 后端 Fastify Server（大脑）

整个系统的"中枢神经"，监听 127.0.0.1:38888。所有前端调用、所有 agent 调度都从这里过。

技术栈

  • 运行时：Node.js ≥ 24（原生支持 node:sqlite）
  • 框架：Fastify ^5.2.0（比 Express 快 2-3 倍，原生 TypeScript 友好）
  • 数据库：node:sqlite 内嵌模块（--experimental-sqlite flag 启动）
  • 语言：TypeScript ^5.7（编译时类型检查）

入口文件：apps/server/src/index.ts

这个文件大约 1800+ 行，包含所有 HTTP 路由定义。从名字可以看出模块划分：

模块文件职责
index.ts主入口，HTTP 路由注册
auth.ts单用户登录 + token 会话
db.tsSQLite 连接 + 迁移（所有表结构都在这）
config.ts路径、token、配置常量
goalNlu.ts自然语言 → Goal 解析（NLU 核心）
workbenchV11.tsWorkbench v1.1 PRD 对应接口
computerUse.ts桌面控制 + 验收截图
evidencePack.ts证据包（截图 + 命令输出）打包
research.tsDeep Research 调度
systemReview.ts系统评审（OpenClaw 配置 / 资源）
mobileTranscription.ts手机语音笔记转写

10 Vibe Coding 怎么用它 — 实战指南

你不需要写代码，但你要会"用自然语言驱动 agent"。这是 Vibe Coding 的核心。

一句话原则

你描述目标 → agent 拆解 → 执行 → 给你证据 → 你验收。不需要懂代码细节，只需要懂"你要达成什么 + 怎么验收"。

4 类高频任务模板

① 修 bug / 改功能

❌ 不好：帮我改一下那个 prompt 文件
✅ 好：在 Chrome 里打开 Workbench 演示笔记生成，重点修复 LLM 调用慢的问题
   （agent 会自动拆解：先查 LLM 慢在哪一步 → 定位行号 → patch → 出截图验证）

② 加新功能

❌ 不好：加一个报表
✅ 好：在 Dashboard 加一张"本月航材订单金额"卡片，
      数据从 opc_orders 表聚合，要求支持按客户筛选，
      验收：截图 Dashboard 新卡片 + 点筛选后数据变化

③ 整理 / 调研

❌ 不好：把笔记整理一下
✅ 好：把知识库里 02_MOC 主题重复的笔记合并，
      每组保留最新版本，其余归档到 .vault_quarantine，
      验收：列出每组保留了哪个、归档了哪几个

④ 系统级操作

❌ 不好：重启一下 server
✅ 好：现在 OpenClaw Gateway 显示 DEGRADED，请帮我看一下原因，
      如果是进程挂了请先告诉我再 kill（按 gate 5 走审批）

Vibe Coding 黄金 4 步

  1. 给方向 + 验收标准（不要说怎么实现，说你要看到什么）
  2. 让 agent 自己决定实施（agent 会拆任务、写代码、跑测试、出截图）
  3. 看证据拍板（截图 + 命令输出 + 测试结果，不要只看"已完成"）
  4. 不通过就反馈（一句话指出来，不要自己动手改 — 那是 agent 的活）

不要做的事

不要绕过 agent 自己改代码 — 改完 agent 不知道，下一轮还会按旧版重做。
不要直接动数据库 — agent 会从代码层读 schema，手改 DB 会跟代码不一致。
不要删 data/backups/ — 那是唯一恢复手段，删了就回不去了。
不要 push 到公网 — 这是 local-only 项目，不推远程仓库（用 git bundle 备份）。

Vibe Coding 的反馈循环

你说一句话 ↓ agent 拆任务 + 跑代码 + 出截图证据 ↓ 你看截图（不看代码）+ 判断是否满足验收 ↓ 满足 → ACCEPT（归档证据） → 下一个任务 不满足 → 反馈一句话 → agent 重做或局部 patch

11 安全边界 — 哪些事我不能干

项目设计上有几道硬边界，agent（和你）都不能越过。

边界含义
不能动 前端 不能直接访问 ~/.openclaw/（必须走后端代理）
不能动 Gateway token / IMA key / OpenClaw credentials 只由服务端读取，前端永远拿不到

4 道人工把关的"硬节点"

1. 战略转向 — 换赛道、砍业务、改产品定位
2. 外部承诺 — 发版、合作、合同、付款
3. 破坏性操作 — 删数据、付费、对外可见
4. 安全边界 — 改 token、密钥、网络配置

其他 95% 的事，agent 自主推进，不打断你（auto-decay 兜底）。
