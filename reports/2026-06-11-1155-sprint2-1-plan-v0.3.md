## Sprint2.1 三个 gap（按优先级）

### Gap 1: Dispatch 失败后**永久 blocked**，不自动 retry

**现状**：
- `runDevelopmentSubtask`（index.ts:17753-17769）—— gateway 失败 → `subtask.status=blocked` + `blockers=["OpenClaw 代理派发失败"]`
- 不会再重试，owner 必须手动调 `actions { action: continue }` 或 `auto_check` 才能推

**用户故事**：
- njx 早上看到 `goal-blocked`，但其实只是 gateway 临时挂了一下
- 应该等下次 heartbeat 自动 retry（如果 retry budget 还在）

**实施方案**（代码路径：apps/server/src/index.ts）：
- 在 `subtask.status=blocked` 的失败路径**同时**加 `retry_at = now + heartbeat_interval_minutes`
- 加 `retry_count` 字段（cap=3）
- `runDevelopmentGoalAutoLoop` scan 时把 `retry_at <= now` 的 subtask 也算 due
- 超过 retry_count → 永久 blocked + 写 `goal_dispatch_recovery` artifact

**验收**：
- ✅ 跑 3 个 gateway 失败 case，subtask 状态：blocked → retry → blocked（attempt 2）→ blocked（attempt 3）→ permanent_blocked
- ✅ audit_logs 看到 3 次 `subtask.run.dispatch` retry events

---

### Gap 2: **Completion audit 不会自动推算 next_heartbeat_at**

**现状**：
- `runDevelopmentGoalAction` action="complete"（index.ts:16160-16247）—— goal 完成后 status=completed，但 **next_heartbeat_at 还停在旧值**
- owner 想再开新一轮必须 PATCH goal 重新设
- chain 体验断在这里

**用户故事**：
- njx 完成 Sprint1 验收 → 想立刻开 Sprint2 1-on-1
- 不该让 njx 手 PATCH

**实施方案**：
- `action="complete"` 成功后，如果 `goal.continues=true`（新加字段）或 `goal.metadata.continueGoal` → 自动 PATCH `auto_run_enabled=1, next_heartbeat_at=now+1min, auto_turns_used=0`
- goal 详情 UI 加个「完成后自动开下一轮」checkbox
- 默认 off（不破坏现有 owner 主导习惯）

**验收**：
- ✅ 一个 goal 完成 → metadata.continueGoal=true → 1 min 内 auto-run 自动起下一轮
- ✅ 同一 goal completion audit score < 75 → 不开下一轮（低分不连环）

---

### Gap 3: **Subtask 完成后 baseline progress 已推进，但 owner UI 没明显提示**

**现状**：
- `runDevelopmentSubtask` 成功路径调 `refreshDevelopmentBaselineProgress`（index.ts:17735）—— 推下一个 subtask 进 active
- 但 `goal.next_action` 没更新，UI 还是显示"继续当前子任务"

**用户故事**：
- njx 早上看 goal 详情，应该看到"刚完成 001，002 进行中"而不是老的"001 进行中"

**实施方案**（轻量）：
- `runDevelopmentSubtask` 成功路径加 `goal.next_action = "子任务 001 已通过，002 接力：拆解实现任务"`
- 加 `goal.last_subtask_passed_at` 字段
- UI Timeline tab 高亮最近 1 个 passed subtask

**验收**：
- ✅ 跑通 1 个 subtask 完整 lifecycle，goal 详情 `next_action` 实时更新
